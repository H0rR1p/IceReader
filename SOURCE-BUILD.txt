IceReader corresponding-source build instructions
================================================

The source archive shipped with a release contains the exact working-tree
application files, their SHA-256 hashes, upstream dependency source archives,
license texts, and build scripts. SOURCE-MANIFEST.json identifies the base
Git commit and the included file snapshot. The snapshot may contain changes
not yet pushed to GitHub; rebuild from the included files, not a moving branch.

Desktop (Windows x64)
---------------------
Requirements: Python 3.12 x64, Node.js/npm, PowerShell, Windows/.NET tools.
Unzip the source archive, then open PowerShell in its IceReader directory:

  py -3.12 -m venv .venv64
  .\.venv64\Scripts\python.exe -m pip install -r backend/requirements-release.txt
  npm ci
  .\.venv64\Scripts\python.exe scripts/prepare_legal.py --fetch
  npm run desktop:build

The regular build uses the same official dependency versions. This needs
network access to download toolchains, wheels and the Electron runtime.
For inspection or native-source builds, dependency-sources/ contains the
original source archives with hashes in SOURCE-MANIFEST.json. Building native
dependencies may additionally require Rust, C/C++, CMake, and their upstream
instructions. The archive does not claim a completely offline toolchain.
Generated source and license materials are under build/legal; every desktop
build checks the source archive and includes them in resources/legal.

Dependency source cache
-----------------------
The legal preparer downloads source distributions from official PyPI/npm
registries and locked native crates from crates.io, verifying published
checksums. The first --fetch creates build/legal-cache; subsequent local
release builds use it offline. Source archives supplied with this release
can also be used directly for review; they are not executable app modules.
Do not substitute a wheel or native binary for an upstream source archive.
The exact version of EbookLib is 0.19; its source and AGPL license are supplied.

YMM4 bridge
------------
The independent bridge source and project are in ymm4-bridge/. The desktop
distribution includes the prebuilt bridge, not YMM4 or its proprietary engines.
To rebuild it, install the .NET SDK for the project's TargetFramework and a
legally obtained YMM4 installation/SDK, then run (with your actual path):

  dotnet build ymm4-bridge/BingduYmmBridge.csproj -c Release -p:YmmDir="C:\YMM4"

Copy the resulting BingduYmmBridge.dll and its deps file to assets/ymm4-bridge
before rebuilding the client. YMM4 and voice-pack terms remain separate.

Desktop native libraries (matching upstream sources)
----------------------------------------------------
This release uses official Electron 42.4.0 Windows x64, with Chromium
148.0.7778.254 and the Chromium FFmpeg fork at
b5e18fb9da84e26ceef30d4e4886696bf59337c0. The supplied native manifest pins
archive bytes, source revisions and hashes of the official runtime libraries.
The application EXE has only its Windows branding/icon resources changed.
The FFmpeg DLL itself is byte-identical to the official release. CONFIG_GPL
and CONFIG_NONFREE are disabled in its Chrome/win/x64 config; it is used under
LGPL-2.1-or-later. Read COPYING.LGPLv2.1 and CREDITS.chromium in the archive.

The following original archives are in dependency-sources/:
- electron-v42.4.0.tar.gz: full application runtime source, GN args, DEPS,
  patches/{chromium,ffmpeg,...}, patch application tools and build instructions.
- chromium-148.0.7778.254.tar.gz: full pinned Chromium repository, including
  Blink, the locally modified libusb, Hunspell, ISimpleDOM, hyphenation data,
  licenses, GN targets and platform integration code.
- ffmpeg-b5e18fb9.tar.gz: the exact Chromium fork, generated Windows x64 codec
  config, build files and upstream copyright notices.
- hunspell-dictionaries-cccf64a8.tar.gz and readability-d7949dc4.tar.gz:
  externally pinned dictionary data and Mozilla Readability source.

To modify/relink native components, follow the pinned Electron source's
/docs/development/build-instructions-gn.md and Windows prerequisites. A full
native build needs a supported Visual Studio C++ toolchain, Windows SDK,
depot_tools, the compiler/sysroots specified by DEPS, Node/Python and ample
disk space. These are not installed in the IceReader workspace. Initialize
Electron at v42.4.0 with gclient according to those instructions; use its
DEPS to obtain the exact additional upstream dependencies and apply its
patches with the supplied patch scripts. The original archives may replace
those checkouts at the matching paths/revisions; for example the FFmpeg fork
belongs in src/third_party/ffmpeg. Do not combine a generic FFmpeg release
with Electron's generated Chromium config or omit Electron's upstream patches.

In that native checkout, use the supplied release args as the starting point:

  gn gen out/Release --args='import("//electron/build/args/release.gn") target_cpu="x64" use_remoteexec=false'
  autoninja -C out/Release ffmpeg
  autoninja -C out/Release electron

The imported release.gn sets is_component_ffmpeg=true. all.gn specifies
Chrome FFmpeg branding; preserve the codec configuration and ABI if replacing
only ffmpeg.dll. Upstream release args can download pinned PGO profiles;
follow the PGO documentation in the supplied Electron source. A non-PGO
local debug/relink build may use the upstream testing.gn args instead; it
is not claimed to reproduce the official binary bit for bit.

For the shared FFmpeg library, quit IceReader, save the installed DLL as a
backup, then replace ffmpeg.dll beside the application EXE with the compatible
rebuilt Windows x64 library. Restart the app to test your library; restore the
backup if its ABI does not match. No signature or project license gate prevents
this replacement. Keep all applicable notices with your modified distribution.
For statically integrated libraries such as Blink/libusb, rebuild/relink the
full Electron runtime with your changes. Use its rebuilt dist as electronDist
in electron-builder.yml, include the new matching sources and update the
native manifest/hashes after review. The normal release gate intentionally
rejects unaudited runtime upgrades; it does not forbid users' modifications.
It is permitted to reverse engineer for debugging modifications to the LGPL
libraries; there is no IceReader EULA restricting that right.

Verification here binds supplied upstream sources/config/patches to the
exact official runtime hashes and checks the packaged libraries again.
The project did not compile Chromium from scratch or claim a bit-identical
native rebuild. See the pinned build instructions for toolchain requirements.
Ordinary IceReader releases rebuild the application around the official
runtime. All current desktop corresponding sources are supplied directly,
without depending on a future written source offer or a moving branch.
